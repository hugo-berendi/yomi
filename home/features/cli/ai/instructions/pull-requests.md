## Pull request descriptions

Write a pull request description for a reviewer who reads it in under a minute.

- Open with one or two sentences: what changes and why.
- Follow with a few short bullets only for what the reviewer needs: the notable
  changes, risks, and anything to check by hand. Leave out what the diff shows.
- Say how it was tested in one or two lines, naming the checks, not pasting
  their output.
- For a visible UI change, add before-and-after screenshots taken from the real
  interface, with arrows where the change is easy to miss.
- No walls of text: no headings on a small PR, no file lists, no repeated commit
  messages, no logs or metric tables. Link to issues, logs and runs instead.
  Detailed evidence belongs in the commit messages.
